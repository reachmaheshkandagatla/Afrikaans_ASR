# Afrikaans ASR Research Framework

This repository provides a reproducible framework for training and evaluating an Afrikaans
automatic speech recognition (ASR) model using OpenAI Whisper. It was developed from an
initial Colab workflow and reorganized into a structured Python project for research,
experimentation, and future model iteration.

The framework focuses on adapting `openai/whisper-large-v3` to Afrikaans speech through
parameter-efficient fine-tuning with LoRA. The pipeline separates data preparation,
dataset validation, model training, evaluation, and Hugging Face Hub publication so that
each research phase can be inspected and repeated independently.

## Research Motivation

Afrikaans remains underrepresented in many modern ASR benchmarks and production-ready
speech systems. While multilingual foundation models such as Whisper provide a strong
starting point, domain-specific adaptation is often required to improve transcription
quality for local accents, recording conditions, vocabulary, and speech patterns.

This project supports research into:

- low-resource and underrepresented-language ASR adaptation,
- Whisper fine-tuning for Afrikaans transcription,
- LoRA-based training under limited compute budgets,
- reproducible dataset preprocessing for speech models,
- word error rate (WER) evaluation of Afrikaans ASR outputs.

## Objectives

The main objectives of this framework are:

1. Convert raw Afrikaans audio/transcript datasets into Whisper-compatible features.
2. Validate mapped data before GPU training to avoid expensive training failures.
3. Fine-tune Whisper Large v3 with LoRA for Afrikaans transcription.
4. Track model quality using WER during evaluation.
5. Save and publish trained adapters and processors for reuse.
6. Provide a clean foundation for future experiments, ablations, and dataset expansion.

## Methodology

The workflow is divided into three research phases.

### Phase 1: Dataset Mapping

Raw Hugging Face `datasets` splits are converted into:

- `input_features`: Whisper log-Mel features generated by `WhisperProcessor`,
- `labels`: tokenizer IDs generated from Afrikaans transcripts.

The expected raw dataset layout is:

```text
datasets_general_v1/
  train/
  val/
```

Each split must include:

- an `audio` column containing waveform array and sampling rate,
- a `text` column containing the Afrikaans transcript.

### Phase 2: Dataset Validation

Before training, the mapped dataset is validated on CPU. This phase checks:

- feature and label types,
- feature and label lengths,
- tokenizer compatibility,
- decoded transcript readability,
- optional forward-pass compatibility with `WhisperForConditionalGeneration`.

This is intended to catch mapping, tokenization, and shape problems before using GPU time.

### Phase 3: LoRA Fine-Tuning

The training phase fine-tunes `openai/whisper-large-v3` using LoRA adapters applied to the
attention projection layers:

- `q_proj`
- `k_proj`
- `v_proj`
- `out_proj`

The default training configuration uses:

- base model: `openai/whisper-large-v3`
- language: Afrikaans, `af`
- task: transcription
- precision: `bfloat16`
- metric: word error rate (WER)
- adapter repo: `rareRabbit/whisper-largev3-afrikaans-lora`

## Installation

Install the project in editable mode:

```bash
pip install -e .
```

For CUDA environments such as Colab or an A100 machine, install the appropriate PyTorch
wheel first if required, then install this package:

```bash
pip install -q torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu118
pip install -e .
```

Log in to Hugging Face before uploading datasets or model adapters:

```bash
huggingface-cli login
```

## Configuration

All major experiment settings are stored in YAML files:

```text
configs/
  mapping.yaml      dataset mapping configuration
  validate.yaml     CPU validation configuration
  train_lora.yaml   LoRA training configuration
```

Update these files to change dataset paths, Hugging Face repo IDs, model IDs, LoRA
parameters, training steps, batch sizes, and output directories.

## Usage

### Map The Dataset

```bash
afrikaans-asr-map --config configs/mapping.yaml
```

To map and upload the processed dataset to Hugging Face:

```bash
afrikaans-asr-map --config configs/mapping.yaml --upload
```

### Validate The Mapped Dataset

```bash
afrikaans-asr-validate --config configs/validate.yaml
```

### Train The LoRA Adapter

Run this stage on a GPU machine:

```bash
afrikaans-asr-train --config configs/train_lora.yaml
```

### Upload Existing Outputs

To upload a saved adapter or checkpoint folder:

```bash
afrikaans-asr-upload \
  --folder /path/to/folder \
  --repo-id rareRabbit/whisper-largev3-afrikaans-lora \
  --repo-type model
```


## Expected Research Outputs

The framework is designed to produce:

- a mapped Afrikaans Whisper dataset,
- CPU validation logs confirming dataset/model compatibility,
- LoRA adapter checkpoints,
- WER evaluation results during training,
- a reusable Hugging Face model adapter and processor.

## Notes On Reproducibility

- Keep dataset versions and Hugging Face repo IDs fixed for comparable experiments.
- Record changes to `configs/train_lora.yaml` for each training run.
- Avoid committing raw audio, mapped datasets, checkpoints, or local cache directories.
- Use the validation phase before every substantial training run.

## Current Default Hub Targets

```text
Mapped dataset: rareRabbit/afrikaans-asr-mapped-largev3
LoRA adapter:   rareRabbit/whisper-largev3-afrikaans-lora
```

These can be changed in the YAML configuration files.
